# 03 · 价值评估

> 版本 v0.1 · 2026-09-15 · 状态：讨论稿
> 结论先行：**效率收益撑不起这个项目，撑得起它的是决策价值和资产价值。**

## 1. 三本账

### 效率账：小而确定
- 每批考察 3–5 人，回来每人花 2–4 小时整理 → 每批省 **10–20 人时**
- 月均 1 批 → 年约 **15–30 人天**
- 判断：真实存在，但单独只够撑"顺手就该做"，不够立项

### 决策账：大而有条件（核心价值）
- 考察背后是**拿地与产品定位决策**：做不做四代宅、户型配比、定价对标
- 现状问题不是没考察，是**考察了但调不出来**——上会靠个人记忆和临时拼凑，对标口径每次重来
- 一次产品定位失手（滞销/降价/去化慢）代价千万到亿级；决策输入质量提升一点，年化价值百万级
- **兑现标志（验证点）：考察纪要出现在下一次投资上会/产品定位会的材料里。** 出现=成立；没出现=只是个整理工具

### 资产账：长期复利
- 置业人员流动不低，成熟投资经理的"看盘记忆"随人流失
- 资产化后：新人 onboarding 从"跟师傅半年"变成"直接调历史库"；横向对标从"问人"变成"查表"
- 见效最慢，滚起来最稳

## 2. 成本对照与投入决策

| 版本 | 成本 | 决策 |
|---|---|---|
| 轻量版（转发→解析→写表→纪要） | ≈ 0，现有工具链直接跑 | **无条件值得做**，效率账已回本 |
| 完整版（自建应用实时采集） | 需 IT 投入 | 跑 3 个月看验证点：纪要进了上会材料就上，没进就停 |

## 3. 价值成立的三条件

1. 考察频次 ≥ 月均 1 批
2. 有明确下游消费场景（投资上会、产品定位会）
3. 置业负责人自己有 ownership

**最大风险不是技术，是没人用**：素材靠群里随手发，负责人不要这个东西，库三个月就是空的。

## 4. 与数智鸿园项目的经验对照

数智鸿园数字化暂停的根因是**组织变革与按旧流程搭建的系统冲突**（2026-06-22 暂停推广，2026-07-30 成立业务标准化小组）。

考察助手的结构性差异：它是**加法型工具**——不改现有流程、不动岗位职责、不逼人切换系统，不触发同类冲突。这是它相对有利的地方，但不能免除"负责人自己要"这一前提。
