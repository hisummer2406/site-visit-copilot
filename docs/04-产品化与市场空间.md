# 04 · 产品化与市场空间

> 版本 v0.1 · 2026-09-15 · 状态：讨论稿
> 结论先行：**软件不赚钱，赚钱的是"方法 + 数据"。先当咨询做，产品化是水到渠成的副产品。**

## 1. 独立 SaaS 的天花板测算

付费市场漏斗（乐观口径）：

```
全国有开发活动房企 约5万家
  → 仍在拿地 + 有投拓团队 1–3千家
    → 月均1批以上考察 约0.5–1.5千家
      → 付费转化 100–300家
```

按 SaaS 定价 2–5 万/年 × 100–300 家 ≈ **2000 万–1.5 亿/年**：养 3–5 人小团队可以，撑不起融资故事。

### 三个结构性风险

1. **切口太薄**：考察记录工具不在任何企业的必买清单上
2. **巨头邻接**：明源云客研模块、中指/克而瑞数据产品、协同平台（飞书/钉钉/企微）的会议纪要 AI 都在往这个空间伸手；你验证了市场，平台顺手覆盖
3. **逆周期**：地产数字化预算坍塌（参照：某集团一期合同约 41 万，比选了 11 家供应商）

## 2. 三条产品化路径

| 路径 | 形态 | 客单价 | 判断 |
|---|---|---|---|
| ① 独立 SaaS | 考察记录工具订阅 | 2–5 万/年 | 天花板低、风险高，不推荐 |
| ② **咨询 + 标准化工具包（推荐）** | "考察资产化"课题：方法论 + 落地 + 首批数据灌入 | 10–50 万/课题 | 切咨询预算而非软件预算；客群=区域腰部房企、城投系置业 |
| ③ 数据对标网络（终局） | 多客户统一 schema 脱敏聚合的考察数据 | 数据订阅 | "好房子时代的民间克而瑞"；最难（权属/脱敏/冷启动），最值钱 |

### 路径②的客群逻辑

头部房企有自己的客研中心；**区域腰部和城投系置业公司正被"四代宅/好房子"政策窗口推着做产品，却没有系统的对标能力**——这是区域性顾问能切的位置。首个服务的客户（某区域集团）就是第一个样板：跑通两批考察、纪要进了上会材料，这个案例就是销售工具。

## 3. 时机判断

- 有利：四代宅/"好房子"政策窗口打开，产品研究需求被政策创造出来
- 不利：地产数字化软件预算坍塌
- 对策：**以咨询课题名目切入，不切软件预算**

## 4. 行动顺序

```
首个客户跑通轻量版 → 纪要进上会材料（验证点）→ 包装"考察资产化"咨询课题对外复制 2–3 单 → 再决定是否正式产品化
```

## 5. 从第一天就要守的约束

**字段 schema 按可跨客户聚合的标准设计。** 将来想聚合多客户数据做对标网络，字段对得上就随时能聚；对不上就永远只是单客户工具。
