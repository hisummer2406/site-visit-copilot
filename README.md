# site-visit-copilot · 地产考察助手

> 状态：**需求讨论阶段（v0.1 讨论稿）** · 建档 2026-09-15
> 原则：先讨论清楚需求，再动手做。本文档库是讨论基线，不是开发计划。

## 一句话定位

将地产置业团队分散在**群聊记录、表格、手机照片、豆包对话**中的考察资料，升级为**可检索、可横向对标**的团队资产。

## 核心结论（详见各文档）

- 卡点不在"记录"，在"结构化"与"横向可比"；豆包对话是价值最高、最难回收的部分，策略是**收编而非回收**
- 方案枢纽是**「考察批次」**：以批次收口采集，批次关闭自动出纪要
- 人的负担压到最低：**考察时随手发，考察后点确认，其余交给智能体**
- 价值排序：效率账小而确定，**决策账大而有条件**（验证点=纪要进入投资上会/产品定位会材料），资产账长期复利
- 产品化路径：**先做案例不做产品**；独立 SaaS 天花板约 2000 万–1.5 亿/年且有巨头邻接风险；推荐"咨询+标准化工具包"切入区域腰部客群；终局是统一 schema 的数据对标网络
- 楼盘客观数据无合法开放的 API 端口，采用**分层背景包**设计：客观数据层（政府+门户公开数据自动预填）+ 主观情报层（自有考察库）
